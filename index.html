Linux System Monitor

A C++ collector samples CPU and memory usage on Linux. A Python service built with FastAPI validates CPU alerts and recovery events, stores them in PostgreSQL, and exposes the event history through an API.

  • Python
  • FastAPI
  • PostgreSQL
  • C++20
  • Linux
  • Docker Compose
View source
Technical details
  • Calculates CPU utilization from changes in Linux counters between samples and uses MemAvailable to estimate memory usage.
  • Tracks alert state so a sustained spike sends one alert and a separate recovery event.
  • Runs the Python API and PostgreSQL in Docker Compose while the C++ collector runs on the host.

Follow a CPU alert

Walk through one alert from the Linux collector to PostgreSQL using an example CPU spike.

System Monitor walkthrough steps
Sample CPU usage on Linux

The C++ collector reads cumulative CPU counters from /proc/stat and measures the change between samples. It also reads memory usage from /proc/meminfo.

CPU sample 1    83%
CPU sample 2    88%
CPU sample 3    92%
Detect a sustained spike

Three consecutive readings at or above 80% trigger an alert. The rule stays active until a reading drops below 80%, which triggers a recovery event.

83%  →  88%  →  92%
                  ↑ alert
Send the alert to FastAPI

The collector sends the event over HTTP. FastAPI validates the event kind and checks that the CPU percentage is between 0 and 100 before saving it.

POST /events
{
  "kind": "alert",
  "cpu_percent": 92.0
}
Read the alert back from PostgreSQL

PostgreSQL assigns an ID and receipt timestamp. GET /events returns the stored history even after the collector exits.

GET /events
[
  {
    "id": 42,
    "received_at": "2026-11-18T18:00:00Z",
    "kind": "alert",
    "cpu_percent": 92.0
  }
]

Concurrent STOMP Messaging System

A Java server and multithreaded C++ client use STOMP over TCP to share sports updates. A Python service records user activity in SQLite.

  • Java
  • C++
  • Python
  • SQLite
View source
Technical details
  • The Java server can use either a thread per connection or a Java NIO reactor backed by a worker pool.
  • The C++ client reads keyboard input and incoming messages on separate threads, so it can receive updates while waiting for a command.
  • The Python service stores registration and session activity in SQLite.

Concurrent Computation Engine

A Java engine that evaluates matrix expressions from JSON. A custom scheduler distributes row-level tasks across worker threads, with read/write locks protecting shared data.

  • Java
  • Multithreading
  • JUnit
View source
Technical details
  • Reads a JSON expression tree and splits each matrix operation into row-level tasks.
  • Uses a custom Java executor that assigns work based on workers’ accumulated execution time and a per-worker factor.
  • JUnit tests cover matrix operations, shared data access, and task dispatch.
